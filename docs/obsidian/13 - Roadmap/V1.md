# Roadmap V1

## Objetivo de V1

Entregar un Turnero estable para Ingreso, operable en producción, con experiencia clara para ingresantes, operadores y administración, y con reglas críticas protegidas en backend.

## Prioridad P0 — estabilidad operativa

- Resolver definitivamente el bloqueo de boxes por históricos.
- Validar llamada, rellamada, inicio y finalización.
- Validar concurrencia entre operadores.
- Mantener producción operable antes de introducir cambios visuales mayores.

## Prioridad P1 — higiene de jornada

- Implementar expiración controlada de históricos.
- Mantener `en_atencion` histórico bajo revisión manual.
- Auditar cada expiración automática.
- Confirmar que métricas y colas se limiten a la jornada correspondiente.

## Prioridad P1 — experiencia del ingresante

- Mostrar siempre **Informes generales** como etiqueta visible, conservando el slug técnico `informes`.
- Consolidar estados: selección, espera, llamado y finalización.
- No simular cancelaciones hasta que backend las soporte de forma real.
- Mantener una acción principal por pantalla.

## Prioridad P1 — operador

- Interfaz más operacional y compacta.
- Jerarquía fuerte del turno actual.
- Controles claros para llamar, iniciar y finalizar.
- Prevención visual de dobles acciones.

## Prioridad P1 — administración

- Dashboard ejecutivo con datos reales.
- KPIs del día.
- Gráficos por categoría y hora.
- Estado en vivo de cola y boxes.
- No inventar comparaciones o SLA sin soporte de datos y definición de producto.

## Prioridad P2 — tótem y pantalla pública

- QR como opción principal del tótem.
- Papel como alternativa visible pero secundaria.
- Pantalla pública simple y legible a distancia.

## Prioridad P2 — rendimiento

- Auditar polling sostenido.
- Evaluar polling adaptativo o Realtime sin cambiar reglas de negocio.
- Repetir pruebas de carga después de cambios relevantes.

## Prioridad P2 — seguridad

- Auditoría RLS/RPC.
- Sesiones y permisos de operadores/admin.
- Secretos y variables públicas.
- Endpoints internos.

## Condición de salida V1

V1 se considera lista cuando:
- los flujos críticos funcionan sin errores P0;
- concurrencia e integridad están probadas;
- no hay históricos interfiriendo jornadas nuevas;
- UX principal está aprobada;
- dashboard operativo muestra datos reales;
- documentación de producto y pruebas está actualizada en este Vault.
